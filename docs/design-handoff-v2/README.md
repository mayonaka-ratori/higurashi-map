# ハンドオフ v2: ひぐらしのなくところに — 案4「今夜の答え」

## これは何か

`docs/design-handoff/README.md`（案B「探して選ぶ」）の**差し替え**。
案Bは実装前にレビューを通し、**採用しないことにした**。代わりに採用したのが案4「今夜の答え」。

判断基準は `AGENTS.md` のまま:
**「この変更で、ユーザーがヒグラシを聞ける確率が上がるか？」**

参照実装（このプロジェクトで実際に動く）:

| ファイル | 画面 | 検証サイズ |
|---|---|---|
| `plan4-answer.dc.html` | PC | 1440×900 |
| `plan4-answer-sp.dc.html` | スマホ | 390×844 |
| `hig-kit.js` | 共有ロジック（♪・朝夕の窓・地図） | — |
| `higurashi-core.js` | 期待度・鮮度・サンプルデータ（既存の移植） | — |

忠実度は**ハイファイ**。下の数値をそのまま使うこと。
例外はサンプルデータと固定時刻（8月7日 18:12）だけ。

## 案Bをやめた理由

案Bは Google Maps 型の左パネル一覧だった。実装前に見直して、次の点で落とした。

1. **一覧が仕事をしていない。** 155か所のうち今日の記録があるのは10件前後。
   残り140件を並べても、読む人がやることは「上から数件見て一つ決める」だけだった。
2. **★がレビュー点数に見える。** 「この公園は★4の公園」と読まれる。
   評価しているのは場所ではなく、その日その時間に鳴いていそうかどうか。
3. **「日の入り前後30分」だけを指していた。** ヒグラシは夜明け前後にもよく鳴き、
   曇りの日や暗い林では日中も鳴く。夕方だけを案内すると、朝に行ける人を取りこぼす。
4. **投稿ゼロの日が設計されていなかった。** ヒーローカードを引っ込めるだけで、
   その日の画面が「機能が減った状態」に見えていた。実際にはゼロの日が一番多い。

## 案4で変わること

### ① 期待度の単位を ★ から ♪ へ

```js
export const notesText = (n) => (n > 0 ? "♪".repeat(n) : "");
```

- 点いた分だけ出す。空の記号は並べない
- 0件のときは**何も出さない**。「—」も置かない
  （同じ行に「今シーズンの記録なし」と出ているので、ダッシュは情報を足さない）
- 色 `#0e7490` / `letter-spacing:.13em`
- サイズ: 一覧14px / PCの答え・詳細19–21px / スマホの答え16px / カード13px
- 添える言葉: `notesLabel()` — `よく鳴いている / 鳴いている / たぶん鳴く / 望みはある / わずか / 記録なし`

**★ の廃止は文言にも及ぶ。** 画面のどこにも ★ を残さない
（「★ではなく♪です」のような説明も書かない。★を知らない人に説明する必要がない）。

### ② 聞きどきは1日2回（朝と夕）

`hig-kit.js` の `listeningWindows(now, lat, lng)` が返すもの:

```
dawn, dusk         Date（夜明け・日の入り）
wins[]             { kind:'dawn'|'dusk', label, center, from, to }  前後30分
active             いま窓の中ならその窓、外なら null
state              「いま聞きどき・朝」「いま聞きどき・夕」
                   「朝の聞きどきはこれから」「夕の聞きどきはこれから」「今日の聞きどきは過ぎた」
remain             「18:58まで あと46分」「あと45分ではじまる」「次は明日の夜明け 4:38ごろ」
tone               'now' | 'soon' | 'past'
note               窓の外の日中 →「曇りの日や暗い林なら、日中でも鳴きます」
                   それ以外    →「鳴くのは夜明けと日の入りの前後30分が中心です」
daytime            朝の窓の後・夕の窓の前なら true
```

夜明けは既存の `sunsetDate` と同じ式の対称側から出している。
実装では `src/lib/sun.ts` に `sunriseDate` と `listeningWindows` を足すこと。

### ③ 時間帯レール（全幅）

案Bのタブ右端の一行テキストをやめ、**1日を横一本の帯にして画面上部に置く**。

- 背景 `#0b3b2e`、トラック `#164b3b`（高さ3px、`border-radius:2px`）
- 朝の窓 `#99f6e4` / 夕の窓 `#fcd34d`（高さ9px、`border-radius:5px`）
- 目盛りラベル `0時 / 6時 / 12時 / 18時 / 24時` — 11px `#a7f3d0`
- 夜明け・日の入りの時刻ラベル — **11px / 700**、窓と同じ色で窓の真下
- 現在時刻 — 幅3px `#ecfdf5`、`box-shadow:0 0 0 3px rgba(11,59,46,.85)`
- **今日届いた報告を時刻の位置に点で打つ**
  - 7px（スマホ6px）の丸、聞こえた `#5eead4` / 静かだった `#94a3b8`
  - `box-shadow:0 0 0 2px rgba(11,59,46,.9)`
  - 上下に交互（`i % 2`）に振って、同時刻の重なりを避ける

帯を見れば「夕方の山に3件かたまっている＝今まさに鳴いている」が読める。
これがこの再設計の中心なので、**レールの文字を9pxにしない**（11px下限）。

### ④ 一覧をやめて、答えを一つ出す

```js
const todayOnes = ranked.filter(r => r.s.freshness === "today");
const answer = todayOnes.length > 0 && todayOnes[0].s.stars >= 3 ? todayOnes[0] : null;
```

- `answer` があれば「今夜はここ」（朝の窓なら「今朝はここ」）＋地点名29px＋♪＋根拠
- `answer` が無ければ**別の画面**に切り替える（下の「⑤空の日」）
- その下に候補を最大5件（PC）／6件（スマホ）

**候補の母集団と見出しは連動させる。**

```js
const others          = ranked.filter(r => !answer || r.p.id !== answer.p.id);
const othersWithRecord= others.filter(r => r.s.freshness !== "none");
const restHasRecords  = othersWithRecord.length > 0;
const restPool        = (restHasRecords ? othersWithRecord : others).slice(0, 5);
```

| | 見出し（答えあり） | 見出し（答えなし） |
|---|---|---|
| `restHasRecords === true` | ほかの候補 | 実績のある場所 |
| `restHasRecords === false` | 近くの場所 | 近くの場所 |

実績が無い行を「実績のある場所」の下に置かない。**画面が嘘をつかないこと。**

### ⑤ 投稿ゼロ／少ない日を、設計された画面にする

`answer` が立たない日は、落ちぶれた表示ではなく別の状態として作る。

- ラベル「きょうの状況」（灰色のドット）
- 見出し
  - 今日の報告が1件でもある → 「確かなことは、まだ言えません」
  - 1件も無い → 「今日はまだ誰も聞いていません」
- 本文（`ans.emptyLead`）
  - 今日の報告あり → 「今日届いているのは N 件だけです。下は実績のある場所を近い順に出しています。」
  - 実績も無い → 「下は現在地から近い場所です。行って聞こえたら、その場で教えてください。」
  - 日中（`daytime`） → 「曇りの日や暗い林なら日中でも鳴きます。下は今シーズン鳴いた実績のある場所です。」
  - それ以外 → 「夜明けと日の入りの前後30分が聞きどきです。下は実績のある場所を近い順に出しています。」
- ボタンは「近い順にならべる」（枠付き・白）に変わる
- 脚注「今日の一件目になれます。聞こえなかったときも「静かだった」を押すと、次の人の役に立ちます。」

**「今日」と「今シーズン」を混ぜない。** その日の状況を言う場所で今シーズンの話をしない。

### ⑥ 投稿を1タップで終わらせる

- 「🌲 いま聞こえた」を**常駐**させる（PC=答えカードの右、スマホ=地図右下のFAB）
- 押すと現在地から近い3件が下からせり上がり、押した時点で送信
- 「この中にない — 地図から選ぶ」で地図選択に落ちる
- 「さっき聞いた分を記録」→ 時刻チップ（さっき / 1時間前 / 今朝 / 昨日の夕方）を選んでから場所

**投稿は地図に効くところまで見せる。** 送信後、その場所のピンが緑になり、♪が増え、
レールに点が増える。完了カードに「この場所のピンが今 🟢 になりました。」を出す。

### ⑦ 二次操作の温度感を分ける

「ひとこと添える」と「さっき聞いた分を記録」は別の種類の行動なので、同じ青リンクで並べない。

| | ひとこと添える（任意） | さっき聞いた分を記録 |
|---|---|---|
| 位置づけ | いま送る投稿への添え物 | 別の入口 |
| 見た目 | `＋` 付きの静かなテキスト、13px `#475569`、下線なし | 枠付きピル、12px/700 `#0f172a`、`border:1px solid #cbd5e1`、`border-radius:9999px` |

2つは行を分けて縦に置く（`flex-direction:column; align-items:flex-start; gap:2px`）。

```
┌─────────────────────┐
│ ヘッダー + データ切替   │
│ 時間帯レール           │
├─────────────────────┤
│                     │
│      地図（最大）      │

```

- 検索 input は **`font-size:16px` 必須**（iOS Safari が16px未満で自動ズームする）
- ◎ は自前ボタン（46×46px、`right:12px; top:76px`）。Leaflet のズームコントロールは隠す
- FAB「🌲 いま聞こえた」は `right:12px; bottom:14px`、`box-shadow:0 5px 18px rgba(5,150,105,.42)`

### 下端カードが動かないこと（重要）

状態が変わるたびにカードの高さが変わると、地図まで伸び縮みして視線が飛ぶ。

- 答えのブロックは **`height:196px` 固定**、`display:flex; flex-direction:column`
- ボタンは `margin-top:auto` で下端に貼る
- 候補カードは **`width:216px; height:104px` 固定**
- 横スクロールは `scroll-snap-type:x mandatory` + カードに `scroll-snap-align:start`、
  `scroll-padding-left:14px`、スクロールバーは隠す

答えあり／1件だけの日／ゼロの日を切り替えても、ボタンと候補列の位置が1pxも動かないこと。

### 詳細シート
- `border-radius:20px 20px 0 0; box-shadow:0 -8px 26px rgba(15,23,42,.26); max-height:76vh`
- 背景オーバーレイ `rgba(15,23,42,.2)`（タップで閉じる）
- **投稿2ボタンは下端固定。** スクロールしても消えない
- ✕ は `padding:11px 13px`（44px相当のタップ域）
- 並び替え「おすすめ順／近い順」にも `padding:14px 10px; margin:-14px -10px` を入れて
  44px を確保する（見た目の位置は負マージンで維持）

## 地図の仕様（案Bから変更なし）

鮮度4段階・ピン半径・パルス・地点名ラベル・リング・タップ判定は
`docs/design-handoff/README.md`「地図の仕様」のまま。`src/lib/score.ts` と
`src/components/MapView.tsx` には**すでに反映済み**。

変更点は2つだけ:

1. **カメラオフセットの符号。** 右パネルなので x を **−202px**（PC）、スマホは y を −110px
2. **ラベルの衝突判定にパネル幅を渡す。** `labelInsetRight`（PC）で、
   パネルの下に地点名が隠れないようにする

参照実装は Leaflet で書いてある。**実装先は MapLibre GL。Leaflet のコードを持ち込まないこと。**
`hig-kit.js` の `syncLabels()` が手で書いている衝突回避は、MapLibre では
`symbol` レイヤーの `text-allow-overlap:false` / `text-variable-anchor` で標準機能として入る。
地点名の白い箱・枠・影は、MapLibreの標準ラベルでは同じ形を作れないため、
実装では白い文字フチで置き換える。

## 文言

**変更禁止の定型文**（案Bから継続）
- キャッチコピー: 「今日、カナカナが聞こえる場所。」
- 投稿完了: 「カナカナ情報を受け取りました。」/「今日ヒグラシを探している誰かの助けになります。」

**案4で足した／変えた文言**

| 場所 | 文言 |
|---|---|
| 答え見出し | 今夜はここ ／ 今朝はここ（朝の窓のとき） |
| 空・報告あり | 確かなことは、まだ言えません |
| 空・報告なし | 今日はまだ誰も聞いていません |
| 空のラベル | きょうの状況 |
| 候補の見出し | ほかの候補 ／ 実績のある場所 ／ 近くの場所 |
| 聞きどき | いま聞きどき・朝 ／ いま聞きどき・夕 ／ 朝（夕）の聞きどきはこれから ／ 今日の聞きどきは過ぎた |
| 聞きどきの補足 | 鳴くのは夜明けと日の入りの前後30分が中心です ／ 曇りの日や暗い林なら、日中でも鳴きます |
| 常駐ボタン | 🌲 いま聞こえた |

## 実装の順番

### 1. ロジック層

`src/lib/score.ts`
- `starsText` を `notesText` に置き換え（`"♪".repeat(n)`、0件は空文字）
- `notesLabel(n)` を追加
- `reasonText` / `rankScore` / `agoText` は案Bのまま追加
- `PlaceStats` に `heardIn3hCount` / `quietIn3hCount` / `todayHeardCount` を追加

`src/lib/sun.ts`
- `sunriseDate(now, lat, lng)` を追加
- `listeningWindows(now, lat, lng)` を追加（上の仕様どおり）

**確認**: ★が画面から消え、♪だけになる。日中に開くと `note` が
「曇りの日や暗い林なら、日中でも鳴きます」に変わる。

### 2. 時間帯レール

新しいコンポーネント。`reports` を props で受け、今日ぶんを点で打つ。
`prefers-reduced-motion: reduce` で点のアニメーションは持たせない（もともと静止）。

**確認**: 目盛り・朝夕の窓・現在時刻・報告の点が全部見える。11px を下回っていない。

### 3. 答えのブロックと空の状態

`answer` / `restPool` / `restHasRecords` の3つを1か所で計算し、
見出し・本文・ボタンをそこから出し分ける。

**確認**: DBを空にした状態で開いて、
- 「今日はまだ誰も聞いていません」＋「近くの場所」になること
- 「実績のある場所」の下に「今シーズンの記録なし」の行が並んでいないこと

### 4. 地図

案Bの `MapView.tsx` から変えるのはカメラオフセットの符号とラベルの右インセットだけ。

### 5. 投稿

- 常駐ボタン → 近い3件 → 1タップ送信
- 既存の `insertReport` / `isThrottled` / `markPosted` / `getPosition` をそのまま使う
- 送信後に `reload()` して、ピンと♪とレールの点が更新されることまで見る
- 失敗時は `postState: {kind:"error"}` の画面を出す

### 6. スマホ

- 下端カードを固定高にする（`196px` + `margin-top:auto`）
- 候補カードを固定サイズ＋スクロールスナップ
- タップ域44px、検索16px

**確認**: 実機か DevTools の 390×844 で、状態を切り替えても地図の高さが変わらないこと。

- [ ] 画面に ★ が1つも残っていない

- [ ] 白の上に `#94a3b8` 以下の薄さの文字が無い
- [ ] `font:inherit` が `font-size` の後ろに書かれていない
- [ ] 155個のピンが出て、🟢今日が大きく濃い
- [ ] 🟢今日のピンだけパルスが動き、ズーム9.8以上で地点名が出て重ならない
