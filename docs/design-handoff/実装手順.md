# 実装手順

`README.md` に全仕様がある。ここは**着手順**だけ。
各段階の終わりで `npm run dev` を開いて、目で見て確認してから次へ進むこと。

---

## 0. 準備

```bash
npm install
npm run dev
```

まず `design/再設計案.dc.html` をブラウザで開き、
上部タブを **案B / PC** と **案B / スマホ** に切り替えて、実物を見ておく。
「今夜のサンプル」と「投稿ゼロの日」の両方を見ること。ヒーローカードの出る／出ないが分かる。

比較用に `design/現行UI.dc.html` も開いておくと、何が変わるのかが分かる。

## 1. ロジック層（`src/lib/score.ts`）

UIに手を付ける前にここを終わらせる。純粋関数なので確認が速い。

1. `FRESHNESS_COLOR` の4色を新しい値に差し替え
   （`#059669` / `#f59e0b` / `#ffffff` / `#94a3b8`）
2. 縁の色・太さも持たせる（`FRESHNESS_STYLE` のような形にまとめてよい）
3. `PlaceStats` に `heardIn3hCount` / `quietIn3hCount` / `todayHeardCount` を追加。
   `placeStats` 内で既に計算している値を返すだけ。**加点ルールは変えない**
4. `starsText` を `"★".repeat(s)` のみに変更（☆を並べない）
5. `agoText` / `reasonText` / `rankScore` を追加

`design/higurashi-core.js` に動くJS版がある。TypeScriptに直して移すだけ。

**確認**: 既存画面の★表示が「★★★」だけになり、☆が消えていること。

---

## 2. 地図（`src/components/MapView.tsx`）

ここが一番のリスク。**Leafletのコードを持ち込まない。** MapLibreの機能で作る。

1. GeoJSON の properties に `freshness` と `score` と `label` を載せる
   （`label` = `p.name.split(/[（(・]/)[0]`）
2. `places-circle` レイヤーの paint を `["match", ["get","freshness"], ...]` で
   鮮度ごとに出し分ける。半径は README の interpolate stops をそのまま使う
3. `circle-sort-key` に鮮度の序列（none=0 … today=3）を入れて、今日を最前面に
4. `symbol` レイヤーでラベルを追加
   - `filter: ["==", ["get","freshness"], "today"]`
   - `text-field: ["step", ["zoom"], "", 9.8, ["get","label"]]`
   - `text-allow-overlap: false` / `text-ignore-placement: false`
   - `text-variable-anchor: ["left","right"]` / `text-radial-offset`
   - `symbol-sort-key: ["-", 0, ["get","score"]]`（期待度の高い順に置く）
   - 背景の白い箱は `text-halo-color:#fff` + `text-halo-width` で代用するか、
     見た目を厳密に合わせたいなら DOM マーカーにする
5. パルスは DOM マーカー（今日のピンぶんだけ、通常10件前後）。
   `prefers-reduced-motion: reduce` で止める
6. hover / 選択のリングを追加（半径17/20、`#0f172a`、太さ3/4）
7. 選択時のカメラオフセットを入れる（PC `+196px` / スマホ `-110px`）
8. `moveend` で現在の bounds を親へ通知（一覧の絞り込みに使う）
9. `GeolocateControl` の `geolocate` イベントで、親の `sort` を `near` にする

**確認（ここは特に念入りに）**:
- ピンが155個出ているか（0個ならワーカーURLを疑う）
- 地図コンテナの高さが0になっていないか
- ズーム9.8前後でラベルが出入りし、**重ならない**か
- 端のピンのラベルが画面外へはみ出していないか

## 3. 一覧と絞り込み（`src/components/App.tsx`）

1. state を追加: `query` / `filter` / `tab` / `sort` / `bounds`
2. 絞り込みの順番は **地図の表示範囲 → 検索語 → 鮮度チップ**
3. 並び替えの2モード（`rankScore` 降順 / 距離昇順）
4. 一覧行を README の寸法で組む。hover で地図のピンにリングが出る配線も
5. 「今日の報告」タブ（全地点横断・時刻の新しい順）

**確認**: 地図をドラッグすると件数が変わる。チップで絞れる。並び替えが効く。

---

## 4. ヒーローカードと聞きどき

1. 母集団 = `freshness !== "none"` の場所のみ。空なら近い順で埋める
2. 上位8件を取る
3. `heroReady = top[0].freshness === "today" && top[0].stars >= 3`
4. 満たさない日は案内文カードに差し替え（**「今夜はここ」と言わない**）
5. `src/lib/sun.ts` で聞きどき（日の入り±30分）の状態文と残り時間

**確認**: DBを空にした状態（またはお試しモードで投稿ゼロ）で開いて、
ヒーローが出ずに案内文になること。

## 5. 詳細と投稿

1. PC: 左パネルの中身を全面差し替え（`position:absolute; inset:0`）。**別ページに遷移しない**
2. スマホ: 下から詳細シート（`max-height:64%`、背景オーバーレイのタップで閉じる）
3. 投稿2ボタンを**下端固定**にする。スクロールしても消えないこと
4. 既存の `insertReport` / `isThrottled` / `markPosted` / `getPosition` をそのまま使う
5. `sending` → `done`。`done` で完了カード、`heard === true` のときだけ 𝕏 シェアボタン
6. エラー時の表示は既存実装のものを残す

**確認**: PCとスマホの両方で、投稿が最後まで通ること。
詳細を一番下までスクロールしてもボタンが見えていること。

---

## 6. スマホのシート

1. 既定は `sheet: "cards"` — 全面地図 + 下端の横並びカード
2. 「一覧を見る 42件」でシートを `max-height:56%` まで上げる
3. 「地図を広く」でカードに戻す
4. 検索 input は **`font-size:16px`**（iOS Safari の自動ズーム回避）
5. タップ域は 44px 未満にしない（✕ボタンの `padding:10px 12px` はそのため）

**確認**: 実機か DevTools の 390×844 で、カードが横スクロールし、
タップで詳細シートが上がり、キーボードを出しても画面がズームしないこと。

## 判断に迷ったら

**「この変更で、ユーザーがヒグラシを聞ける確率が上がるか？」**

このデザインで足したものは全部これに YES で答えられる:
- ピンの大小 → 今日行ける場所が一目で分かる
- ラベル → 地名を読むためにクリックしなくてよくなる
- 距離込みの並び → 「★5だが80km先」が1位に来なくなる
- 下端固定の投稿ボタン → 現地で片手で押せる
- ヒーローの条件分岐 → 根拠のない日に断定しない（外れを掴ませない）

迷ったものは作らない。`VISION.md` の禁止リストを先に見ること。
