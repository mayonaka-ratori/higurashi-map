## 製品の芯（デザインの出発点）

ユーザーが知りたいのはただ一つ——**「今日行けば聞ける？」**。
画面を開いて3秒で「今日は◯◯に行けば聞けそうだ」が分かること。
それ以外の要素はすべて脇役。装飾のための装飾はしない。

参考にする水準: Google Maps。地図が主役で、情報は地図を隠さず並走し、
どの縮尺でも「いま何を見ているか」が分かる。

## 現状のUI

1画面構成。実装は [src/components/App.tsx](../src/components/App.tsx)（画面全体）と
[src/components/MapView.tsx](../src/components/MapView.tsx)（地図）。

- 下: パネル（未選択=おすすめ5件リスト / 選択時=地点詳細＋投稿2ボタン）

スマホ向けには調整済みで、そちらのレイアウトは概ね維持してよい。
**問題はPC（横長画面）で、スマホのレイアウトをそのまま引き伸ばしているだけ**なこと。

## PCでの問題点（実スクリーンショットで確認済み）

1. **下パネルが全幅** — 投稿ボタンが横1000px超のバナー状になり、
   視線が地図と情報の間を大きく往復する。地図を見ながら地点情報を読めない
2. **ピンに名前が出ない** — ホバーしても無反応。どの丸がどの公園か、
   タップして下パネルを見るまで分からない。Google Mapsとの最大の差
3. **文字が小さすぎる** — ヘッダー・凡例はスマホ向けサイズ（10〜11px）のままで、
   大画面では読めない飾りになっている
4. **情報密度が低い** — 画面の大半が無情報の空白。おすすめリストは5件だけ、
   広い地図にピンが数個。「どこを見ればいいか」の手がかりが薄い
5. **ピンの存在感が弱い** — ⚫記録なし（スレートグレー）が地図に沈む。
   逆に🟢今日確認が目立ち切れていない。選択中のリング（水色）も細い
6. **ホバー・フォーカス状態が未設計** — マウス環境の作法（hover強調、
   キーボード操作、カーソル変化）がほぼ無い

## 目指す姿（提案。デザインセッションで再検討してよい）

- **PC（md以上）**: Google Maps型の**左サイドパネル＋全面地図**。
  パネル幅360〜420px固定。未選択=おすすめリスト（件数も増やす）、
  選択時=地点詳細。地図は常に見えている
- **スマホ**: 現行のボトムシート方式を維持
- **地図上の地点名ラベル**: ズームが一定以上のとき、ピンの脇に地点名を表示。
  少なくともホバーでツールチップ表示（後述の技術メモ参照）
- **ピンの再設計**: 鮮度4色の視認性を上げる。🟢は「今日聞ける」の主役として
  最も目立たせる。サイズ・縁取り・必要なら形状で差をつける
- **文字サイズの段階設計**: スマホとPCでタイポグラフィを分ける

## 変えてはいけないもの

- 定型文3つ: 「今日、カナカナが聞こえる場所。」
  「カナカナ情報を受け取りました。」「今日ヒグラシを探している誰かの助けになります。」
- 鮮度の色の**意味**（🟢今日 / 🟡3日以内 / ⚪今シーズン / ⚫記録なし）。
  色の具体値は改善してよいが、4段階の区別と直感（緑=行け）は守る
- 投稿は2ボタンで5秒以内。投稿フローに画面遷移や入力必須項目を足さない
- 匿名・登録なし。 [VISION.md](VISION.md) の「絶対に作らないもの」
- 世界観は少しだけ。詩的にしすぎない（アプリ内テキストの流儀はAGENTS.md参照）

## 技術メモ（デザイン実装時の制約）

- Tailwind CSS v4 / Next.js App Router。ブレークポイントは Tailwind標準（md=768px）を想定
- 地図はMapLibre GL v6。**ワーカーと地図コンテナの2つの落とし穴**が
  [AGENTS.md](../AGENTS.md) に書いてある。必読
- **地図上に日本語テキストを出すにはglyphs（フォントデータ）の指定が必要**。
  現状のスタイルには未設定なのでsymbolレイヤーの文字は出せない。選択肢:
  1. ホバーツールチップをHTML（DOM）で出す — glyphs不要で一番軽い。まずこれを推奨
  2. glyphsを設定して地図に焼き込む — 見た目はGoogle Maps級になるが、
     フォント配信元（例: glyphs.geolonia.com の無料サービス）への依存か、
     public/へのフォント自前配置（要事前生成）が必要
- スポットは155箇所（今後増える）。全件描画でも問題ない規模だが、
  ラベルは重なり制御が必要
- 色はTailwindのパレットで統一している（emerald系がブランド色）

## 完成の判定基準

- 初見のPCユーザーが、操作説明なしで3秒以内に「今日期待できる場所」を見つけられる
- 地図上のピンが何の場所か、クリックせずに分かる（ホバーまたはラベル）
- スマホの使い勝手が悪化していない（ボトムシート・48pxタップ領域・16px入力欄を維持）
- 「ヒグラシを聞ける確率が上がるか？」に照らして、足した装飾を一つずつ説明できる
