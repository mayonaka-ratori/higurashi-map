# UI/UX改修プラン 2026-08（承認済み・実装用）

作成 2026-08-18。ユーザー承認済み。opus 3体によるコード突き合わせレビューを反映済み（v2）。
このファイルは**別セッションが実装するための指示書**。
実装者は着手前に [AGENTS.md](../AGENTS.md) 全文（特に「地図UIの決まり」「落とし穴」）と
[SPEC.md](SPEC.md) を読むこと。判断に迷ったら唯一の判断基準

## 決定事項（チャットで確定した前提）

1. 方針は「スマホ最優先・投稿は1〜2タップ・電波とGPSが悪い屋外を標準場面とみなす」。
2. **未登録の場所への投稿（自由報告ピン）を入れる。** ただしスポットの新規作成ではない。
   名前なし・「聞こえた」だけ・座標は約100mに丸める。スポットのキュレーション体制は変えない。
3. 自由報告ピンの表示期間は**登録スポットと同じ鮮度3段階**
   （🟢今日 / 🟡3日以内 / ⚪今シーズン）。シーズン内はずっと地図に残る。
4. データは消さない。表示期間はあくまで見た目の話で、DBの記録は恒久に残る
   （reports テーブルは update/delete を誰にも許可していない）。
5. **すべての投稿の緯度経度を送信前に小数3桁（約100m）へ丸める**（自由報告に限らない）。
   reports テーブルは誰でも読めて誰にも消せないため、生のGPS座標を恒久保存しないのが目的。
   期待度のGPS高精度加点（+10）が見ているのは accuracy だけで（score.ts:108付近）、
   緯度経度は現在アプリのどこからも読まれていないので、丸めても何も壊れない。
   accuracy は丸めずそのまま送る。
   **丸めを入れる場所は `store.ts` の `insertReport` の先頭**（latitude / longitude が
   null でなければ丸める）。本番・デモ・キュー経由のすべてがここを通るので1か所で済む。
   App側（doPost や postFreeReport）に置かないこと——置き忘れた経路が生座標のまま残る。

**問題**: クイック投稿シートを開いた直後、現在地が取れるまで（最長6秒）は

「近い3件」の位置に並ぶ。急いでいる人が間違った場所へ投稿しやすい。

**変更**:

- `App.tsx`: `openQuick` で現在地が未取得のとき `locating`（boolean state）を立て、

- `QuickPostSheet.tsx`（mode "now"）の全状態を1つの表で確定させる。

  **フェーズ0時点では📍列と「静かだった」行はまだ無い**（③と1で順に足す）が、
  完成形をここに書いておく:

## フェーズ0-① 圏外でも投稿を失わない（送信キュー）

**問題**: 圏外・通信失敗だと投稿が捨てられ、「もう一度送る」を手で押すしかない。
山あい・夕暮れの利用場面では圏外が普通にある。

### insertReport の改修（失敗の分類は store.ts に閉じる）

いまの `insertReport` は `{ error }` しか見ておらず、通信失敗とサーバー拒否を
呼び出し側で区別できない（supabase の postgrest-js は fetch 例外も
`{ message: "TypeError: Failed to fetch", status: 0 }` 形の error にして返す。
**error.message の文字列で判定する実装は禁止**）。次のように変える:

- `insertReport` の戻り値を
  `{ ok: true } | { ok: false; retryable: boolean }` に変える。
  **絶対に throw しない関数にする**: デモモードの `localStorage.setItem` も try/catch で囲み、
  失敗したら `{ ok: false, retryable: false }` を返す
  （throw が残ると、catch を外した呼び出し側で未処理エラーになり
  画面が「送信中…」のまま固まる）。
- 分類は応答の `status` で行う（`const { error, status } = await supabase!...` で取れる）:
  - `status === 0`（通信失敗）または `navigator.onLine === false` → `retryable: true`
  - `status >= 500`、`status === 408`、`status === 429`（サーバー側の一時障害・レート制限）→ `retryable: true`
  - それ以外の 4xx（ポリシー違反・制約違反など。何度送っても通らない）→ `retryable: false`
- デモモードは従来どおり localStorage に書いて `{ ok: true }`。

### 送信キュー（store.ts）

- localStorage キー `higurashi-post-queue`、上限20件。
- `enqueueReport(r: NewReport): boolean`:
  - `created_at` が未指定なら**積んだ時点の時刻**を入れて保存する（「聞いた時刻」が保たれる）。
  - 満杯（20件）のとき、または localStorage への書き込みに失敗したときは
    **積まずに false を返す**（呼び出し側は従来のエラーカードを出す。
    「保存した」と表示して実際は保存しない嘘を作らないため）。
- `flushQueue(): Promise<boolean>`（1件でも送れたら true）:
  - モジュールスコープの再入ガードを置く（`let flushing = false;` 実行中なら即 return false。
    online イベントと1分タイマーが重なって同じ投稿が2回入るのを防ぐ。
    reports は一意制約が無く誰にも消せないので、重複は入れたら終わり）。
    **フラグは try/finally で必ず false に戻す**——途中の失敗で true が残ると、
    以後キューが二度と流れず、貯めた投稿が静かに死ぬ。
  - 先頭から順に `insertReport`。1件成功する**たびに** localStorage を保存し直す。
  - `ok: false, retryable: true` → そこで中断し、残りは次回へ。
  - `ok: false, retryable: false` → その1件を捨てて先へ進む。
  - **`created_at` が now − 47時間より古い項目は送らずに捨てる**
    （insertポリシーの2日制限に必ずかかるため。基準は積んだ時刻ではなく created_at。
    「昨日の夕方」の投稿は積んだ時点で既に丸1日前なことに注意）。
  - デモモードでは何もしない（デモモードではそもそも積まれない。次項）。
  - 残る小さな穴として「insert 成功と localStorage 保存の間にタブが閉じると、次回もう一度
    送られて重複しうる」があるが、これは許容する（コメントで残してよい）。

### doPost（App.tsx）の変更

- `catch {}` をやめ、`insertReport` の戻り値で分岐する:
  - `ok: true` → 従来どおり完了カード。
  - `ok: false, retryable: true` **かつ `!demoMode`** → `enqueueReport` へ。
    積めたら `markPosted`（連投防止は通常どおり効かせる）＋ 新しい投稿状態 `queued`。
    積めなかったら従来のエラーカード。
  - それ以外 → 従来のエラーカード。
- 送信前に **`!demoMode && navigator.onLine === false`** なら、試さずに直接キューへ
  （デモモードは通信を使わないので、この分岐に入れてはいけない。
  入れると flush されないキューに積まれて投稿が永久に消える）。

### フラッシュの呼び出し口（App.tsx）

**`reload` 自体には手を入れない**（`flushQueue` の中から `reload` を呼ぶ自己再帰も作らない）。
既存の `useEffect`（起動時＋1分間隔）のコールバックを次の形に変え、
`online` イベントリスナーからも同じ関数を呼ぶ:

```ts
const tick = async () => { await flushQueue(); reload(); };
// 起動時: tick()
// setInterval(tick, 60 * 1000)
// window.addEventListener("online", tick)
```

### 「あとで送ります」カード

- `src/lib/view.ts` の `PostState` に `{ kind: "queued"; heard: boolean }` を追加し、
  `PlaceDetail.tsx` の投稿状態カードに1枚追加する。完了カードの構造を流用:
  - 見出し「あとで送ります」
  - 本文「いまは電波が届かないようです。この端末に保存したので、電波が戻りしだい自動で送ります。」
  - 「もう一度送る」ボタンは**出さない**（自動で送るため。二重送信の入口を作らない）。
    代わりに done カードと同じ「閉じる」を置き、押すと状態を idle に戻す。
- 色は design.ts の `C` に3つ追加して使う（この計画で確定済みの値。既存の
  danger 3点セットと同じ役割分担）:
  `amberBg: "#fffbeb"`（面）/ `amberBorder: "#fde68a"`（枠）/ `amberText: "#92400e"`（文字）。

**受け入れ条件**: DevToolsのオフライン切り替えで投稿 → 「あとで送ります」カード →
オンラインに戻す（online イベント）→ 自動送信されてピンに反映される。
online イベントと1分タイマーが重なっても同じ投稿が2件入らない。
お試しモード（環境変数なし）ではオフラインにしても従来どおり即時保存で成功する。

## フェーズ1 自由報告ピン

登録スポットの外で「いま聞こえた」を記録できるようにする。データ構造は
reports テーブルの `place_id` を空にできるようにするだけで、位置は既存の
latitude / longitude 列を使う。

### 1-1. DBマイグレーション

`supabase/migrations/2026-08-19-free-reports.sql` を作る（**二度流しても落ちない形**にする）:

```sql
-- 自由報告（登録スポット外での「いま聞こえた」）を受け付ける。
-- place_id が無い行は、座標が必須になる。
alter table public.reports alter column place_id drop not null;
alter table public.reports drop constraint if exists reports_location_required;
alter table public.reports add constraint reports_location_required
  check (place_id is not null or (latitude is not null and longitude is not null));
```

- **`supabase/schema.sql` も同じ内容に更新する**（create table の `place_id text not null` から
  not null を外し、check 制約を足す）。schema.sql は「まっさらなプロジェクト用」の台本なので、
  マイグレーションだけ足すと新規構築時に今回の変更が抜ける。
  2026-08-09 のマイグレーションも schema.sql に反映済みという前例に合わせる。
- **実行はユーザーがSupabaseのSQL Editorで行う**。エージェントは流せないので、
  ファイルを作ってコミットしたら実行を依頼し、完了の返事を待つこと。
- 旧アプリは常に place_id を送るので、このマイグレーションは先に流しても壊れない。
  **順番はマイグレーション → アプリのデプロイ**。
- 未適用のままアプリだけ新しくなった場合、自由報告の送信はサーバーに拒否される
  （4xx → 既存のエラーカード）。専用の分岐は作らない。
- ROADMAPに未完了として残っている `2026-08-09-created-at-from-app.sql` が適用済みかも
  あわせて確認する。ユーザーは非エンジニアなので、**そのまま貼れる確認SQLを渡す**:

```sql
-- これをSQL Editorで実行して、結果を貼り返してもらう
select polname, pg_get_expr(polwithcheck, polrelid) as with_check
  from pg_policy where polrelid = 'public.reports'::regclass;
select is_nullable from information_schema.columns
  where table_schema = 'public' and table_name = 'reports' and column_name = 'place_id';
```

  with_check に `created_at` の条件が出ていれば 2026-08-09 は適用済み。
  is_nullable が YES なら今回のマイグレーションも適用済み。

### 1-2. 型とデータ層

- `src/lib/types.ts`: `Report.place_id` と `NewReport.place_id` を `string | null` に変える。
- `App.tsx` の `statsById` の集計ループ: `place_id` が null の行はスポット集計に入れない
  （`if (!r.place_id) continue;`）。スポットの期待度計算は一切変えない。
- 自由報告の抽出と地図用の集計を `App.tsx` に `useMemo` で足す:
  - 抽出: `reports.filter(r => !r.place_id && r.latitude != null && r.longitude != null && r.heard)`
  - 集計: 丸め座標（小数3桁）が同じものを1点にまとめ、
    `{ lat, lng, count, latestAtMs, freshness }` の配列にする。
    **鮮度はこの useMemo の中で確定させる**（MapView には `now` が渡っていないので、
    MapView 側で計算しようとすると詰まる）。
  - GeoJSON の properties に載せるのは `freshness`（文字列）/ `count`（数値）/
    `latestAtMs`（数値）だけにする。Date オブジェクトを入れない——MapLibre は properties を
    ワーカーへ渡すため、数値・文字列・真偽値以外は式（`["get", ...]`）から読める保証がない。
    吹き出し側は `latestAtMs` から Date に戻す。
- 鮮度の境界は登録スポットと完全に揃える: **score.ts の placeStats 内にある判定
  （`startOfDay(now)` 基準の暦日判定）を `freshnessOf(lastHeardAt: Date, now: Date): Freshness`
  として切り出し、placeStats と自由報告の集計の両方から呼ぶ**。
  「24時間以内=今日」のような独自解釈をしない（0時をまたいだ瞬間にピンとずれる）。
- 座標の丸めは決定事項5のとおり**全投稿共通**（`Math.round(x * 1000) / 1000`）。
  doPost の送信直前に入れれば、自由報告側にも自然に効く。
- `fetchReports` は変更不要（place_id が null の行も同じ select で返ってくる）。

### 1-3. 投稿の入口（QuickPostSheet）

- `mode === "now"` かつ「聞こえた」選択中だけ、候補リストの**いちばん上**に
  「📍 いまの場所で記録する」を置く（状態ごとの出し分けはフェーズ0-②の表のとおり）。
  - 見た目は候補行と同じ枠・同じ高さ。左端は鮮度ドットの代わりに 📍。
    補足行は「地図に名前が無い場所でも記録できます」
    （「登録された場所」という区分の言葉は画面に出さない。画面で説明していない概念のため）。
- **状態管理は `PostState` を流用しない。** App.tsx に専用の state（例 `freePostState`）と
  専用の関数 `postFreeReport()` を新設する。理由: 既存の `postState` は PlaceDetail に
  直結しているため、共有リンク（`/?place=…`）で地点詳細が開いたまま自由報告を送ると、
  無関係な地点の詳細に「この場所のピンが今 🟢 になりました。」が出る事故になる。
  `doPost` と `lastPost` はこのフェーズでは**それ以上変えない**
  （フェーズ0-①で入れた変更はそのまま残す。自由報告を doPost に通さない、という意味）。
- `postFreeReport()` の中身:
  1. `isThrottled("free")` なら弾く。このときのメッセージは
     「続けての記録は2分あけてください。」（既存の「同じ場所への投稿は…」は
     場所を移動した人には嘘になるため、自由報告用の文にする）
  2. `getPosition()` を呼ぶ。**null なら送らず**、シート内にエラー表示
     「現在地が取れないため、いまの場所では記録できません。近くの場所から選んでください。」
     （check制約で必ず弾かれる行を送らない。お試しモードでも同じ扱いにする。
     座標なしで localStorage に入れると、成功に見えて地図に一生出ない報告になる）
  3. 丸め座標で `insertReport({ place_id: null, heard: true, ... })`。
     `created_at` は指定しない（今このときの報告なので）。
  4. 成否の分岐はフェーズ0-①の doPost と同じ（retryable ならキューへ）。
     シート内の「あとで送ります」表示は、0-①で決めたカード（見出し・本文・「閉じる」・
     amber系3色）をそのまま流用する。新しい文言を作らない。
  5. 成功したら `markPosted("free")` → 完了表示 → `reload()`。
- シートは閉じず、**見出し行より下の中身すべて**を「送信中…」→ 完了表示に差し替える
  （候補リストだけでなくチップも「この中にない」ボタンも消す）。
  面・枠・角丸・ボタン寸法は PlaceDetail の完了カードから流用する。
  - 完了表示: 定型文「カナカナ情報を受け取りました。今日ヒグラシを探している誰かの助けになります。」
    ＋「いまの場所に 🟢 が付きました。」（既存カードの語彙「ピンが今 🟢 に」に揃えた言い方）
    ＋「𝕏 でシェアする」＋閉じるボタン。閉じるとシートごと閉じ、状態を idle に戻す。
  - Xシェアの文言（地点名なし）: 「ヒグラシの声を確認しました🌲 #ひぐらしのなくところに」、
    URLはトップ（`window.location.origin`）。
- 登録スポットへのクイック投稿は現状どおり地点詳細へ遷移する。そこは変えない。

### 1-4. 地図表示（MapView / MapOverlay）

**データの配線（ここを漏らすとピンが永久に出ない）**:

- `MapView` に props `freeReports`（1-2で集計済みの配列）を追加し、`dataRef` にも入れる。
- 新しい GeoJSON ソース `free-reports` とレイヤー `free-circle` を追加する。
  **`places-hover` より前に addLayer し、登録スポットのピンの下に敷く。**
- `setData` は2か所で呼ぶ:
  1. `places` と同様の `useEffect`（依存配列に `freeReports` を入れ、
     既存と同じ `if (!map || !readyRef.current) return;` のガードも付ける。
     ガードを落とすと初期化中に getSource が undefined で落ちる）
  2. **`map.on("load")` のハンドラ内**（既存の places の setData と並べる）。
     地図は PC⇔スマホの幅切り替えで作り直される（初期化 useEffect が `[variant]` 依存）ため、
     ここで入れ直さないと、幅をまたいだ瞬間に自由報告ピンだけ消える。

**見た目**:

- 鮮度は3段階（today / recent3d / season）、色は `FRESHNESS_COLOR` をそのまま使う。
  シーズン外の報告は fetch の時点で来ないので分岐不要。
- 大きさは登録スポットより一段小さく、ズーム連動:
  zoom 8 で today 4.5 / recent3d 3.5 / season 2.5、
  zoom 11 で 6.5 / 5 / 3.5、zoom 14 で 9 / 7 / 5。
  縁取りは白 1.5px（season のみ `C.muted` 1.25px）。
  ラベルなし・波紋なし・ホバーリングなし。`circle-sort-key` で 今日>3日>今季。

**タップの吹き出し（新規に作る。既存ツールチップの流用では出ない）**:

- 既存のPCホバーツールチップは `pc &&` で閉じているうえ位置が mousemove 依存なので、
  流用できない。**見た目の数値だけコピーする**（MapOverlay.tsx のツールチップから:
  背景 C.white / 枠 C.border2 / 角丸10px / padding 9px 13px / 同じ boxShadow）。文字は11px以上。
- `MapView` に `onFreeTap(info, point: {x, y})` と `onFreeTapClear()` のコールバックを足す:
  - 既存 click ハンドラで `places-circle` に当たらなかったとき、同じ10px判定で
    `free-circle` を調べる。当たったら `onFreeTap` を呼び、**`onSelect(null)` は呼ばない**
    （呼ぶと吹き出しを出した瞬間に選択解除の副作用が走る）。どちらにも当たらなければ従来どおり。
  - `info` は `queryRenderedFeatures` が返す feature の properties
    （`freshness` / `count` / `latestAtMs`）から作る（集計配列の元オブジェクトは取り出せない）。
  - 地図の `move` で `onFreeTapClear()` を呼ぶ。
- `MapOverlay` に吹き出し用の props を足し、**`pc &&` を掛けない**ブロックとして描く
  （スマホのタップが主戦場）。位置は**既定で点の上側**
  （既存ツールチップと同じ `translate(-50%,-100%)` の向き）。上に入らないときだけ下側に出し、
  左右は地図の幅の内側にクランプする。スマホ右下の🌲ボタンとは重なってよい
  （吹き出しは一時表示で、地図タップですぐ消えるため）。
- 文言は普通の文で終わらせる。当日:「今日 18:42 にこの辺りで聞こえました（2件）」、
  当日以外:「8/16 にこの辺りで聞こえました」。件数は2件以上のときだけ付ける。
  時刻が出せるのは当日だけ（それ以外は日付のみ）。地点詳細のような画面は**作らない**（名前がないため）。

### 1-5. 答えのブロックへの一行（PCのみ）

- `userPos` があり、3km以内に今日の自由報告があるとき、**PCの footnote を差し替える**。
  対象は `buildAnswerVM` の **answer なし側（isEmpty）の footnote だけ**。差し替え後の全文:
  「あなたの近く（3km以内）でも、今日◯件の確認があります。聞こえなかったときも「静かだった」を押すと、次の人の役に立ちます。」
  （既存 footnote の「静かだった」の案内は残す。フェーズ0-③で入口を増やした案内文を消さないため。
  「今日の一件目になれます。」の文は、近くに確認がある状況では事実と合わないので落とす）
  answer あり側の footnote は ♪ の意味の説明を兼ねているので触らない。
  実装は App.tsx で `{...vm, footnote: ...}` と上書きする形でよい（view.ts の分岐を増やさない）。
- **スマホには footnote を描画する場所がそもそも無い**（AnswerBlock.tsx の footnote はPC分岐のみ）。
  スマホの答えカードは高さ固定196pxで、**カード内に行を足すことは禁止**（確定デザインを壊す）。
  スマホでは何も足さない。自由報告は地図の点そのもので見える（スマホは地図が主画面）ので、
  ここで無理に文字で伝えない。
- 距離計算は既存の `distanceKm`（score.ts）を使う。

### 1-6. 時間帯レールと今日件数の扱い（意図の確定）

- `todayReports` は place_id を見ずに全報告を拾う。**フィルタを足さないこと。**
  これは次の2か所に効いていて、どちらも**自由報告を含めるのが意図どおり**:
  - 時間帯レールの点（自由報告も「今日の耳の記録」なので点として出す）
  - `buildAnswerVM` の `hasTodayReports` / `todayReportCount`
    （「今日届いているのは N 件だけです。」の N に自由報告が数えられるのは正しい。
    実際に届いた報告だから。見出しが「今日はまだ誰も聞いていません」から
    「確かなことは、まだ言えません」に変わるのも正しい挙動）
- 1-5 のPC footnote（近くの件数）と N が同じ報告を二重に数えて見える場面があるが、
  意味が違う（Nは全体、footnoteは近所）ので許容する。

### フェーズ1の受け入れ条件

- 登録スポットが1つも近くにない場所で、🌲 → 📍 の2タップで投稿が完了する。
- 投稿した点が地図に出て、翌日は🟡、4日後は⚪になる（時刻をずらしたテストデータで確認。
  0時またぎの境界が登録スポットのピンと同じ基準で切り替わる）。
- **PC幅とスマホ幅を行き来しても自由報告ピンが消えない。**
- 共有リンク（`/?place=…`）で地点詳細が開いた状態から自由報告を送っても、
  その地点の詳細に完了カードが出ない（シート内にだけ出る）。
- 登録スポットの期待度・おすすめ順・「今夜はここ」に自由報告が混ざらない。
- お試しモード（環境変数なし）でも一連の流れが動く（localStorage保存。
  現在地が取れないときは送信前に止まる）。
- `npm run build` が通り、`/verify-map` で実表示を確認済み。
