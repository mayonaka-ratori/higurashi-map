# 地図の実表示確認の手順

AGENTS.md「変更報告の決まり」のとおり、地図まわりは**ブラウザで実際に見えるか**まで
確認しないと完了扱いにしない。画面部品の存在チェックだけでは、高さ0やワーカー死亡の
ような不具合を見逃した実績がある。この手順で確認する。

## 手順

1. `preview_start` に `{name: "higurashi-dev"}` を渡して開発サーバーを開く（.claude/launch.json 定義済み）。
2. **そのタブを必ず前面にする**（`tabs_select`）。MapLibre は requestAnimationFrame で描くため、
   バックグラウンドのタブでは `load` すら発火せずピンが1つも出ない（AGENTS.md 落とし穴5）。
   コードの不具合と間違えやすいので、確認前に必ず前面化する。
3. `read_console_messages` でエラーを確認する。特にワーカー読み込み失敗
   （maplibre-gl-worker.mjs の404など）が出ていないか。
4. `computer {action: "screenshot"}` で目視確認する:
   - 地図タイルが出ているか（灰色一枚なら異常）
   - **ピン（色付きの丸）が出ているか**。1つも無ければ落とし穴1（ワーカー）か
     落とし穴2（コンテナ高さ0）を疑う
   - 時間帯レール・答えのブロックが出ているか
5. UIの変更内容に応じて操作確認する: ピンをクリック → 詳細パネルが出るか、
   投稿ボタンが下端に固定されているか、など。`read_page` と `computer` を使う。
6. スマホ幅も見る: `resize_window {preset: "mobile"}` → ページをリロード → screenshot。
   下端の固定カードとシートの動きを確認する。確認後はPC幅に戻す。
7. 影響がある変更なら `npm run build` も通す。

## 報告の形式

**確認できたこと**と**確認できていないこと**を分けて書く。
例:「ピン表示・詳細パネル・スマホ幅はブラウザで確認済み。実機のGPS投稿は未確認」。
スクリーンショットを根拠として添える。
